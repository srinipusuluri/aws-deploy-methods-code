Claude Chatbot on AWS

Build, deploy and verify all seven levels. Manual console steps are written as prompts for Claude in Chrome.

Before you begin

This repository builds all seven levels. Code lives in backend/, templates in infrastructure/, the website in frontend/. Anything that is not a code or CLI action is a manual step, written as a prompt you can give to Claude in Chrome.

Safe use of browser automation. Use a sandbox or dev AWS account and an IAM role with only the permissions you need. Keep the preamble below on every prompt. You sign in, complete MFA and paste secrets yourself. Read each summary before replying OK. The prompts are written to stop and ask before any change.

Preamble to put before every prompt

Safety preamble
You are helping me with AWS console setup. Rules: (1) If a sign-in, MFA or CAPTCHA appears, stop and tell me; I will do it. (2) Never read, copy, type or repeat secret values (API keys, passwords, tokens) - when a secret must be entered, stop and let me type it. (3) Before any Create / Save / Delete / Deploy click, tell me exactly what you are about to change and wait for my OK. (4) Work only in region <REGION> and only on resources whose names start with <STACK>. (5) If a page does not match these instructions or a button is missing, stop and describe what you see instead of guessing.

Replace <REGION>, <STACK>, <SITE_DOMAIN> and other angle-bracket values with yours before copying.

Tools you need

  • AWS CLI and SAM CLI, configured with a profile (aws sts get-caller-identity works)
  • Python 3.12+, Node optional. pip install -r backend/requirements.txt pytest then pytest -q (15 tests)
  • Chrome with the Claude in Chrome extension, signed in to AWS

Level 1-2: Basic Q&A and multi-turn

Source: backend/level1_basic, backend/level2_conversation   Template: infrastructure/level1-2.yaml

What was built: POST /chat. Level=1 takes {question}; Level=2 takes {messages} (validated, merged, last 12 turns). Throttled HTTP API, CORS locked to your origin, Secrets Manager key, 25 s timeout.

1. Deploy (CLI)

bash
scripts/deploy.sh 1-2 chatbot-l1 AnthropicSecretArn=<SECRET_ARN> ClaudeModel=<MODEL_ID> AllowedOrigin=https://<SITE_DOMAIN> Level=1

Set LEVEL to 1 or 2 and API_URL in frontend/config.js.

2. Manual steps

Claude in ChromeCheck the API route, CORS and throttling

Confirms the settings that protect a public endpoint.

Prompt for Claude in Chrome
Open the API Gateway console at https://<REGION>.console.aws.amazon.com/apigateway. Open the HTTP API named like <STACK>-Api. Report: (a) the routes, (b) CORS configuration - allowed origins must be exactly https://<SITE_DOMAIN>, (c) stage throttling limits. Do not change anything; tell me if CORS shows '*'.

Expected: One route POST /chat; one allowed origin; burst 20 / rate 10.

Claude in ChromeTest the Lambda from the console

Proves the secret, model ID and code work before the browser is involved.

Prompt for Claude in Chrome
Open the Lambda console, find the function named like <STACK>-ChatFn, open the Test tab, create an event named hello with this JSON: {"body": "{\"question\": \"Say hi in five words\"}"}. Ask me before running Test (it calls the paid API). After my OK run it and report the response status and body.

Expected: statusCode 200 with an answer. If 500, open Monitor > View CloudWatch logs and report the last error line (not any message text).

Claude in ChromeSet log retention

Avoid logs growing forever.

Prompt for Claude in Chrome
Open CloudWatch > Log groups, find /aws/lambda/<STACK>-ChatFn, and set retention to 30 days. Wait for my OK before saving.

Expected: Retention 30 days.

Level 3: Login and saved chats

Source: backend/level3_chat   Template: infrastructure/level3.yaml

What was built: Cognito invite-only user pool with Hosted UI + PKCE, JWT-authorized HTTP API, DynamoDB sessions and messages. Every key derives from the token's sub; ownership is checked on read, update and delete.

1. Deploy (CLI)

bash
scripts/deploy.sh 3 chatbot-l3 AnthropicSecretArn=<SECRET_ARN> ClaudeModel=<MODEL_ID> AllowedOrigin=https://<SITE_DOMAIN> CallbackUrl=https://<SITE_DOMAIN>/ CognitoDomainPrefix=<UNIQUE_PREFIX>

Set LEVEL 3, API_URL, COGNITO_DOMAIN and COGNITO_CLIENT_ID from the stack outputs.

2. Manual steps

Claude in ChromeInvite your first user

Users cannot self-register.

Prompt for Claude in Chrome
Open Amazon Cognito > User pools > the pool named like <STACK>-UserPool > Users > Create user. Choose 'Send an email invitation', enter the email I give you (ask me), set custom:tenant_id to default if shown, and keep 'Mark email as verified' checked. Wait for my OK before Create user.

Expected: User in status FORCE_CHANGE_PASSWORD; invite email sent.

Claude in ChromeVerify the app client and Hosted UI

Callback URL must match the site exactly or login fails with redirect_mismatch.

Prompt for Claude in Chrome
In the same Cognito user pool open App integration. Report: the Cognito domain, and for the app client: allowed callback URLs, OAuth grant type (must be Authorization code), scopes, and whether a client secret exists (it must not). Do not change anything.

Expected: Callback = https://<SITE_DOMAIN>/, grant = code, no client secret.

Claude in ChromeConfirm the JWT authorizer

Prompt for Claude in Chrome
Open the API Gateway console > the HTTP API > Authorization. Report the authorizer's issuer URL and audience, and which routes have it attached. All four routes must have it. Do not change anything.

Expected: Issuer https://cognito-idp.<REGION>.amazonaws.com/<pool-id>, audience = app client id.

Claude in ChromeCheck table protection

History is user data: confirm encryption and recovery.

Prompt for Claude in Chrome
Open DynamoDB > Tables. For tables named like <STACK>-SessionsTable and <STACK>-MessagesTable report: encryption, point-in-time recovery status, and billing mode. Do not change anything.

Expected: PITR enabled, SSE on, on-demand.

YouSign in and chat

End-to-end test.

Expected: Open the site, sign in, chat; refresh and confirm the chat list and history persist. In a second account confirm you cannot open the first user's chat.

Level 5: Tools and agents

Source: backend/level5_agent   Template: infrastructure/level5.yaml

What was built: POST /agent runs a bounded (4-step) tool loop. lookup_order and list_orders are read-only and keyed by the verified user. create_support_ticket is queued as PENDING and only runs after POST /agent/approve (idempotent, expires in 1 hour). Every tool use is audited. Arguments are validated against JSON schemas.

1. Deploy (CLI)

bash
scripts/deploy.sh 5 chatbot-l5 AnthropicSecretArn=<SECRET_ARN> ClaudeModel=<MODEL_ID> AllowedOrigin=https://<SITE_DOMAIN> CallbackUrl=https://<SITE_DOMAIN>/ CognitoDomainPrefix=<UNIQUE_PREFIX>

Set LEVEL 5. The UI shows an Approve button for each pending action.

2. Manual steps

Claude in ChromeFind your user's sub

Orders are keyed by the Cognito sub.

Prompt for Claude in Chrome
Open Cognito > User pools > the pool named like <STACK>-UserPool > Users, open the user whose email I give you, and tell me the 'User ID (sub)' value.

Expected: A UUID.

Claude in ChromeAdd demo orders in DynamoDB

Alternative to scripts/seed_orders.py.

Prompt for Claude in Chrome
Open DynamoDB > Tables > the table named like <STACK>-OrdersTable > Explore table items > Create item. Switch to JSON view and create an item {"customer_id": {"S": "<SUB>"}, "order_id": {"S": "1001"}, "item": {"S": "Mechanical keyboard"}, "status": {"S": "SHIPPED"}}. Use the sub I give you. Ask me before saving, then repeat for order_id 1002 (USB-C dock, PROCESSING).

Expected: Two items visible in Explore items.

YouTest the agent

Ask: 'Where is order 1001?' then 'Open a ticket: my dock arrived damaged'. Click Approve.

Expected: Answer cites the order status; the ticket request appears as a button and nothing is created until you approve.

Claude in ChromeReview the audit trail

Every tool call should leave an event.

Prompt for Claude in Chrome
Open DynamoDB > the table named like <STACK>-AgentTable > Explore items. Report how many items start with AUDIT# and list their 'event' values (tool_read, tool_write_queued, tool_write_executed) and any TICKET# items. Do not change anything.

Expected: Events for each step, one OPEN ticket.

Level 6: Production scale

Source: backend/level6_scale (+ level3_chat with quota)   Template: infrastructure/level6.yaml

What was built: Level 3 chat plus per-user daily quotas (atomic DynamoDB counter), reserved Lambda concurrency, API throttling, POST /jobs (202 + Idempotency-Key) with SQS, a worker with partial-batch failure reporting, a dead-letter queue (3 receives), CloudWatch alarms to SNS, and X-Ray tracing. The SDK handles retries; there is no second retry wrapper.

1. Deploy (CLI)

bash
scripts/deploy.sh 6 chatbot-l6 AnthropicSecretArn=<SECRET_ARN> ClaudeModel=<MODEL_ID> AllowedOrigin=https://<SITE_DOMAIN> CallbackUrl=https://<SITE_DOMAIN>/ CognitoDomainPrefix=<UNIQUE_PREFIX> AlertEmail=<YOU@EXAMPLE.COM> DailyLimit=100

Deploy frontend.yaml with ApiDomain so CloudFront serves /api, then attach WAF to CloudFront (WAF cannot attach to HTTP APIs).

2. Manual steps

YouConfirm the alert subscription

SNS will not send until the email is confirmed.

Expected: Open the 'AWS Notification - Subscription Confirmation' email and click Confirm subscription.

Claude in ChromeCreate the WAF web ACL for CloudFront

CloudFront-scoped WAF must be created in us-east-1 (Global).

Prompt for Claude in Chrome
Open https://us-east-1.console.aws.amazon.com/wafv2/homev2/web-acls and choose scope 'Global (CloudFront)'. Create web ACL named chatbot-waf. Add managed rule groups: AWS-AWSManagedRulesCommonRuleSet and AWS-AWSManagedRulesKnownBadInputsRuleSet. Add a custom rate-based rule named rate-per-ip: 300 requests per 5 minutes per IP, action Block. Default action Allow. Do not associate resources here. Summarize and wait for my OK before the final Create. Then tell me the web ACL ARN.

Expected: Web ACL exists; you have its ARN.

CLIDeploy the site stack with WAF

Pass the ARN and API host.

Expected: sam deploy -t infrastructure/frontend.yaml --stack-name chatbot-site --resolve-s3 --capabilities CAPABILITY_IAM --parameter-overrides ApiDomain=<API_ID>.execute-api.<REGION>.amazonaws.com WebAclArn=<WEB_ACL_ARN>. Then set API_URL to /api in config.js.

Claude in ChromeVerify the alarms and the queue

Alarms are what wake you up.

Prompt for Claude in Chrome
Open CloudWatch > Alarms. Report the state of every alarm whose name contains <STACK>; then open SQS and report, for the queues named like <STACK>-JobsQueue and <STACK>-JobsDlq: messages available, messages in flight, and the dead-letter settings (max receives must be 3). Do not change anything.

Expected: Alarms OK or Insufficient data; DLQ empty.

Claude in ChromeCreate a one-page dashboard

Latency, errors, queue depth, quota rejections.

Prompt for Claude in Chrome
Open CloudWatch > Dashboards > Create dashboard named chatbot-prod. Add line widgets for: Lambda Duration and Errors for the ChatFn and WorkerFn, API Gateway 4xx and 5xx and Latency, SQS ApproximateNumberOfMessagesVisible for the DLQ. Ask me before the final Save.

Expected: Dashboard saved.

CLILoad and abuse tests

Prove the controls work before real users do.

Expected: Send 30 rapid requests and confirm 429s from throttling; set DailyLimit=2 and confirm the third chat returns 429 'Daily usage limit reached'; send the same /jobs request twice with one Idempotency-Key and confirm one SQS message.

Level 7: Governed enterprise platform

Source: backend/level7_platform   Template: infrastructure/level7.yaml

What was built: POST /v1/chat gateway: tenant from the verified token only, tenant must be onboarded, DLP and size policy (blocked requests are audited by hash, not content), atomic per-tenant daily token budget, model router with fallback (Anthropic primary, Bedrock fallback), versioned prompts, audit records, and an evaluation gate script (scripts/eval.py) for CI.
