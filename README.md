# AWS Deploy Methods: Claude Chatbot in Seven Levels

Reference implementation of a Claude-powered chatbot on AWS, built up in seven releases from a public Q&A demo to a governed multi-tenant AI gateway. Each level has its own source folder and SAM template. Manual console steps are written as copy-paste prompts for **Claude in Chrome**.

> Status: unit tests pass and the templates pass `cfn-lint`. The stacks have not been deployed from this repository yet, so run the first deployment in a development account.

## Levels

| Level | What it adds | Source | Template | Routes |
|---|---|---|---|---|
| 1 | Single question and answer | `backend/level1_basic` | `infrastructure/level1-2.yaml` | `POST /chat` |
| 2 | Multi-turn chat (validated browser history) | `backend/level2_conversation` | `infrastructure/level1-2.yaml` | `POST /chat` |
| 3 | Cognito login, DynamoDB chat history | `backend/level3_chat` | `infrastructure/level3.yaml` | `POST /chat`, `GET /chats`, `GET /chats/{chatId}`, `DELETE /chats/{chatId}` |
| 4 | RAG with Bedrock Knowledge Bases, tenant filter | `backend/level4_rag` | `infrastructure/level4.yaml` | `POST /ask` |
| 5 | Tool-calling agent with human approval | `backend/level5_agent` | `infrastructure/level5.yaml` | `POST /agent`, `POST /agent/approve` |
| 6 | Quotas, async jobs (SQS + DLQ), alarms, WAF on CloudFront | `backend/level6_scale` | `infrastructure/level6.yaml` | chat routes, `POST /jobs`, `GET /jobs/{jobId}` |
| 7 | Tenant-aware gateway: DLP, token budgets, model routing, audit | `backend/level7_platform` | `infrastructure/level7.yaml` | `POST /v1/chat` |

## Layout

```
backend/shared/        helpers and provider adapters (Anthropic API, Amazon Bedrock)
backend/level*/        one folder of Lambda source per level
infrastructure/        SAM templates (generated by build_templates.py) and frontend.yaml
frontend/              static chat UI, Cognito PKCE login, config.js
scripts/               deploy.sh, create_user.sh, seed and upload scripts, eval.py, build_guide.py
tests/unit/            15 unit tests
data/                  sample document and golden evaluation questions
docs/                  deployment-guide.html (open in a browser)
```

## Quick start

Requirements: Python 3.12+, AWS CLI and SAM CLI with a configured profile.

```bash
pip install -r backend/requirements.txt pytest
pytest -q

# Level 1 example
scripts/deploy.sh 1-2 chatbot-l1 \
  AnthropicSecretArn=<secret-arn> ClaudeModel=<model-id> \
  AllowedOrigin=https://<site-domain> Level=1
```

Then open the guide: **[live page](https://srinipusuluri.github.io/aws-deploy-methods-code/)** (GitHub Pages, served from `docs/`) or `docs/deployment-guide.html` locally. See the **[architecture diagram](https://claude.ai/artifact/PRyHLrGGeWCy4wZZvmj2xu)** for how the levels fit together. Every level has its deploy command and its manual steps, each with a prompt you can give to Claude in Chrome and the result to expect.

## Design decisions

- **Secrets:** the Anthropic key lives only in Secrets Manager. The browser never holds a key.
- **Identity:** user and tenant come from the validated JWT, never from request bodies. Every database key is built from it.
- **Timeouts:** Lambda is set to 25 seconds, below the roughly 30 second API Gateway limit. Slow work goes through SQS.
- **Retries:** the Anthropic SDK retries. There is no second retry wrapper.
- **WAF:** attached to CloudFront, because HTTP APIs cannot attach WAF directly.
- **Embeddings:** Anthropic has no embedding model, so Level 4 uses the one in Bedrock Knowledge Bases.
- **Model IDs:** passed as the `ClaudeModel` parameter. Check the Anthropic docs for current IDs.

## Safety with browser automation

Use a sandbox AWS account, a least-privilege role, and keep the safety preamble from the guide on every prompt. Sign in, complete MFA and paste secrets yourself.

## Regenerating generated files

```bash
python3 infrastructure/build_templates.py   # templates

```
